# 《菜农部落》底层运行逻辑设计规范（Design Skill）

> **这是什么**：一份讲清「**哪些量该设为变量（数据）、哪些该写成函数（规则）**」的底层设计尺子，
> 供本项目（及同类回合制小游戏）复用。**不是空谈**——结论全部来自真实踩坑（见第八节，
> 对应 2026-10-10 修复的 4 个 bug）。
>
> **和另两份文档的分工**：
> `SPEC.md` = 游戏**机制**的唯一事实来源（规则是什么）；本文件 = **代码怎么组织**的依据（规则该写成什么）；
> `../AGENTS.md` = 接手者视角的**架构约定与历史坑**。
>
> 参考框架：Robert Nystrom《Game Programming Patterns》（来源见文末）。

---

## 0. 一句话原则

**数据只描述「现在是什么」，函数只描述「规则怎么算」。**

- **数据（变量 / 字典）**是**名词**：可序列化、会随对局变化、能被规则读取或写回。
- **函数（规则）**是**动词**：只读写**传进来的**数据，不持有自己的状态，不碰 DOM。

一句话判据：**「这个量，四个部落会不一样吗？」**
- 会不一样 → 放进**字典**（数据）。
- 四个部落永远一样 → 放进**规则/常量**（函数，或 `RULES`）。

---

## 1. 三分类：什么放数据、什么放函数、什么放常量

| 类别 | 判断标准 | 本项目落点 | 例子 |
|---|---|---|---|
| **数据 · 变量/字典** | 会随对局变化；要被规则读写；要能存盘/序列化 | `src/tribes.js`（部落字典）、`G`（牌局状态） | `money` / `pos` / `seeds` / `hand` / `lands` / `landOwners` / `order` / `turn` |
| **函数 · 规则** | 描述「怎么判定 / 怎么结算」；同一规则对所有对象一致 | `src/engine.js`（框架函数） | `plant()` / `buyLand()` / `harvest()` / `stepMove()` / `traitSeedCost()` |
| **常量 · 配置** | 全局固定，只有调平衡时才改；不随对象变 | `RULES` / `TRACK` / `CROPS`…（`src/data.js`） | `passRate` / `winMoney` / `START_BONUS` / `plots` |

> **禁止**：把「常量」硬编码进函数体（散落的魔法数）；把「规则」写进数据（字典里不该有 if）。
> 调平衡只改 `RULES` 一处，四个部落自动生效。

---

## 2. 「设为变量很好」的量 —— 好数据长什么样

一个量适合做**变量（放进字典/状态）**，当且仅当满足下列多数特征：

1. **每对象各一份**：`money`、`pos`、`lands`、`hand`…（每个部落独立）。
2. **会随操作变化**：种完地 `lands[idx].crops` 变长、买完地 `landOwners[idx]` 被写。
3. **被多个规则读取**：`player.pos` 同时被 `buyLand()` 与 `plant()` 读（→ 位置门槛）。
4. **需要能存/读**：`JSON.stringify(G)`、`localStorage`、测试里直接改字段驱动场景。

满足这些的，就该是**数据**，且**只放原始事实**（「我有什么」），**不放规则结论**。

---

## 3. 「不该做变量」的量 —— 派生量要现算

能由别的数据**算出来**的，**不要再存一份**（两份会打架，是 bug 温床）：

- ✗ 不要存 `player.landCount` → 用 `countLands(player)` 现算。
- ✗ 不要存 `player.totalProfit` → 用 `plantingProfit()` / `harvest()` 的返回值现算。
- ✗ 不要把「展示值」（面板进度百分比、顶栏数字）写回状态 → 渲染时现算。

**判据**：存下来会不会出现「A 改了、B 没跟着改」的不一致？会 → 它是派生量，现算。

---

## 4. 函数该怎么切

1. **一条规则只写一次**。
   `traitSeedCost(player, cropId, cost)` 写一次，集市价 / 图鉴 / 日志**全都调它**，
   就不会出现「三处价格不一致」。（Bug3 的根因正是各写各的。）
2. **纯函数 + 显式传参**。
   `plant(g, player, idx, cropId, count)`：只改**传进来**的字典，不读全局、不碰 DOM。
   DOM 只在 `main.js`（UI 层）。这样引擎能被 `node test/*.js` 直接驱动。
3. **判定与结算分离**。
   前置条件不满足 → `return { ok:false, msg }`；满足才改状态。
   调用方（UI/AI）据 `ok` 决定播报或提示，**不重复实现判定**。
4. **函数名 = 规则名**，不要叫 `handleXxx` 这类含糊名。

## 5. 状态机：回合的唯一驱动

整个回合由一条状态机推进，**真人与 AI 共用同一条序列**（否则「引擎测得对、UI 里不一样」）：

```
① stepRoll（清标记/刷追风/监狱判定/掷骰）
 → ①b stepExtraRoll（追风追加，可选）
 → ② stepMove（一次走完所有步数；只在最终落点结算）
 → ③ stepSettle（落格结算：土地/站点）
 → ④ 决策（买地/种植/收获/用卡）
 → ⑤ stepEnd（胜负判定 + 换手）
```

**关键约束**：决策发生在**移动落格之后**，不是回合开始。
（历史教训：曾同时有「回合开始」和「落格后」两次 `aiPlan()`，电脑一回合决策两遍，平衡崩。）

## 6. 位置信息要用「索引表」，且多表必须同序

赛道是 32 格的**内容**与**坐标**分离：

| 表 | 用途 | 文件 |
|---|---|---|
| `TRACK` | 格子**内容**（哪种土 / 哪个站） | `data.js` |
| `CELL_POS` | 格子**中心坐标**（棋子定位） | `cellPositions.js` |
| `CELL_RECTS` | 格子**矩形框**（卡面 / 点击区） | `cellPositions.js` |

改任何一张，**另两张必须同步**（跑 `test/track.test.js` 校验）。
一个概念涉及几张表，测试就要覆盖几张——这是「数据驱动」的代价，也是它的纪律。

---

## 7. `seat` 与 `turn` —— 最易踩的「两个位置概念」

```
seat = 部落坐在第几号位，0~3，永远不变（players 数组下标）
turn = 行动顺序里的第几位，每局随机，存在 G.order
```

**铁律**：当前行动者 = `g.players[g.order[g.turn]]`。`g.players[g.turn]` 是**错的**。

| 用途 | 该用 |
|---|---|
| 回合流程（掷骰/换手/AI） | `curPlayer(g)` / `cur()` / `curSeat()` / `isAITurn()` |
| 展示给玩家看的东西（面板/弹层/集市/落格操作） | `viewMe()`（local 模式下与当前行动者**不同**） |

同理，「经过的格子集合 `passed[]`」与「最终落点 `player.pos`」也是两个概念，
**只该对落点结算**（Bug2 就是拿 `passed` 当落点用）。

## 8. 反模式清单（本项目真实踩过的坑）

| 反模式 | 真实表现（bug） | 正确做法 |
|---|---|---|
| 把「会变的假设」写死成代码 | 开局**永远玩家先手**，与随机顺序自相矛盾 | 先手读 `order[0]`，谁排第一谁先走 |
| 同一规则在多处各写一遍 | 集市价 ≠ 实际扣款 ≠ 日志金额 | 收敛成 `traitSeedCost()` 一个函数，全处调它 |
| 拿「经过集合」当「落点」 | 路过他人土地也收过路费 | 只对 `idx === player.pos` 结算 |
| 同一门槛只在一处加 | 买地查了 `pos`、种植没查 → 站在 a 也能种远方的 b | 「同一把尺子」：买地与种植都要求 `player.pos === idx` |
| 用派生量当状态 | 存了个 `totalX`，改了源数据忘了同步 | 现算，不存 |

> 这四条，就是 2026-10-10 那轮修复的 4 个 bug。**「数据 vs 规则」划错，几乎都会以这类形式冒出来。**

---

## 9. 落地检查清单（改动前自问）

- [ ] 我加的这个量，是**原始事实**还是**能算出来的**？能算 → 别存，写函数。
- [ ] 我这条规则，**别处是不是也写过一遍**？写过 → 抽成一个函数。
- [ ] 我写死的这个值，**换个局面还成立吗**？不成立 → 它该是数据/参数。
- [ ] 我读的是「当前行动者」还是「面板主人」？—— `cur()` 还是 `viewMe()`？
- [ ] 涉及多张索引表（TRACK/POS/RECTS）时，我是不是都改了、都测了？
