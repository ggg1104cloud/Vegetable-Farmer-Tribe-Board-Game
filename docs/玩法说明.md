# 菜农部落 · 网页版

把桌游《菜农部落》做成浏览器里直接能玩的 2D 网页游戏。
底图是一张国风中国地图（`assets/board_new.jpg`）；**32 个赛道格、卡面、卡位牌全部用 SVG 现画**（半透明宣纸卡座 + 墨线框 + 回纹 + 朱砂印），浮在地图上，任意缩放都不糊。

---

## 怎么跑

需要本地服务器（用了 ES Module，`file://` 会被浏览器拦）：

```bash
cd cn-village
python -m http.server 8932
```

打开 **http://127.0.0.1:8932/index.html**

## 两种对局模式

顶栏右侧可切换，切换会自动重开一局：

| 模式 | 说明 |
|---|---|
| **本地对战** | 四个部落都由真人轮流点击操作，适合同桌玩 |
| **单机模式** | **开局可选部落**：四张部落卡任选其一当主角（电脑控制其余三个）；**电脑每执行一步停 3 秒**，日志逐条播报，看得清它在想什么 |

单机模式下**真人先手**（`G.turn = HUMAN_SEAT`），否则选了非 A 部落时一开局就得干等三个电脑各走完。

## 开局基础种子卡

每局开始时，**每个部落各自**从作物池里随机抽 3 张候选，其中 **2 张直接进手牌**作为
基础种子卡，其余种子只能靠**种子集市**购买。

- 各部落拿到的基础种子**互不相同**（独立随机）
- 手牌种子在种植时优先消耗、不重复扣钱，省下的成本全额计入那片作物的利润
- 日志会逐部落播报「抽到候选 [X、Y、Z]，其中 A、B 作为基础种子卡入库」

`RULES.seedDraw = 3` / `RULES.seedKeep = 2` 可调。
**对平衡的影响**：每张种子卡省一次种子钱（20~70 币），开局购买力约多 20~40%，
平均局长从 ~27 回落到 ~20 次行动。四部落胜率 spread 仍在 9% 以内。

## 查阅科普（跳百度百科）

土地信息卡、种子卡、改良卡手牌都带「🔍 查阅科普」入口，新标签页打开百度百科，
让学生把游戏里的数值和现实概念对上。

链接统一挂在 `src/data.js` 末尾（`wikiItem()` / `wikiSearch()` + 三张映射表），
启动时注入到 `LANDS` / `CROPS` / `IMPROVES` 的 `wiki` 字段：

- **确认存在的词条** → `baike.baidu.com/item/<词条>` 直达正文
  （如 棕壤、水稻土、砖红壤、测土配方施肥、蚯蚓、腐殖质、地膜覆盖、滴灌…）
- **游戏化命名、拿不准的** → `baike.baidu.com/search?word=<词>` 站内搜索页，**永不 404**

共 33 条（11 土地 + 10 作物 + 12 改良）全部配好。

## 部落特长

每个部落绑定一条与自身文化地理相关的特长，会真实影响结算：

| 部落 | 标识 | 特长 | 效果 |
|---|---|---|---|
| A | 华表（中原） | **沃野中原** | 在华北平原的土壤（山东棕壤、黄绵土）上收获，**收益 +90%** |
| B | 三星堆面具（四川） | **稻作之源** | 种植**水稻**种子成本**减半**，收获水稻**收益 +25%** |
| C | 琵琶（西北） | **追风千里** | **每 2 回合**可追投 1 颗「追风骰」（1~3 点），步数累加继续走 |
| D | 彩陶骆驼（丝路） | **丝路商队** | 每次经过起点**额外 +15**（50+15=65） |

加成在**选种弹层就显示出来**（朱砂红标签标注），收获按钮也会预告预计收益，
玩家看到的数字和实际结算完全一致。

**初始金额可调**：顶栏「设置」→ 四个数字输入框，改完「保存并重开」生效，存 localStorage。
默认 150 / 175 / 195 / 210（150 + 先手补偿 0/25/45/60）。

### 作物卡与改良卡是两套手牌

| 手牌 | 来源 | 用途 |
|---|---|---|
| **作物卡**（底栏绿色小标签） | 种子集市买 | 种植时优先消耗，**一片一张**（省掉这一片的种子钱）；同一作物最多囤 3 张、合计最多带 6 张 |
| **改良卡**（底栏大图） | 抽卡 / 改良站 | 抽到即得面值肥力币，持有期间按面值折算增益；点击 = 纯弃牌 |

选作物时会标出三种来源的成本：`手中 ×n · 免费` / ~~原价~~ <s>划线</s> <b>折扣价</b> / 原价，
以及部落特长加成（朱砂红标签）。

## 已实现的规则

| 机制 | 实现 |
|---|---|
| 部落 | 4 个，各有初始作物与特长 |
| 初始资金 | 默认 150/175/195/210（可调） |
| 胜利线 | 累计 **260** 肥力币 |
| 骰子 | 每回合 2 个 d6；C 部落每 2 回合可追投 1 颗（1~3 点） |
| 经过起点 | **+50**（D 部落 +80） |
| 免费买地卡 | 每人初始 1 张 |
| 过路费 | 走到他人土地，付该地价的 **50%**（地价的一半） |
| 土地价格 | 11 种土壤各有定价（荒漠土 40 ~ 东北黑土 120） |
| 肥力→片数 | 低 1 片 / 中 2 片 / 中高 3 片 / 高 3 片（**上限**，可少种：1~上限之间自选） |
| 作物适配 | 适配土壤高收益、非适配低收益（如马铃薯：沙土 35 / 黏土 20） |
| 气象站 | 抽 6 张气象卡之一，**对所有作物统一奖惩**（原版 BUG，故意保留） |
| 土壤改良站 | 抽改良卡到手牌，**抽到即得面值肥力币**（+5 ~ +20），持有期间按面值折算增益 |
| 种子集市 | 摆出**全部 10 种**作物卡，买下即进**作物卡手牌**（单种最多囤 3 张、合计最多 6 张）；之后种植时**优先消耗手牌、不再重复付种子钱**，利润里把省下的种子成本算回去 |
| 监狱 | 经过后暂停一回合 |

### 课程用的 4 个科学性 BUG（内置保留）

1. **土壤数据缺失** —— 肥力只分低/中/中高/高三档，没有颜色、pH、质地实测数据支撑
2. **改良成本一刀切** —— 荒漠盐碱土和东北黑土的改良卡价格完全一样，违背因地制宜
3. **生物改良无长效** —— 堆肥和化学改良都是一次性收益，混淆了理化改良与生物改良的本质
4. **气象损益统一** —— 梅雨对水稻和小麦同样奖惩，忽略作物习性差异

## 视觉风格：优美国风

统一语言：**宣纸底 + 墨线双框 + 回纹角饰 + 朱砂印章 + 楷体**。

所有卡面由 `src/cardArt.js` 用 SVG 现画，任意尺寸清晰、文案改一处即生效：

| 生成函数 | 用在哪 |
|---|---|
| `landCard / landMini` | 土地卡：地貌水墨小景 + 土名/地价/肥力 |
| `cropCard` | 作物卡：白描作物图 + 高收/低收两块对比 + 种子成本 |
| `improveCard` | 改良卡：白描图标 + 单色底纹 + 面值 |
| `cellTile` | 赛道 32 格：土地格画地貌小景、站点格画印章徽章 |
| `deckSlot` | 图板中央三块卡位牌（土壤改良卡/气象卡/土壤信息卡）：主题色卡背 + 两层微旋转宣纸片 |

四大部落标识（华表 / 三星堆面具 / 琵琶 / 彩陶骆驼）同样是 SVG 现画，见 `src/motifs.js`，
带线性渐变做金属反光与陶器质感，通过 `data:` URI 注入棋子与面板。

界面立体感不依赖 3D，靠多层 `box-shadow`（亮内描边 + 暗内描边）、`linear-gradient` 受光面、
反向 `inset` 凹陷三样手法做出来。

## 每回合每块地只能种一轮

沙土（低肥力）只能种 1 片。如果不限制，玩家可以「种一块 → 立刻收 → 再种」的无限循环，
低肥力的地反而成了刷钱最快的地方。

 `player.harvestedThisTurn[idx]` 在 `harvest()` 时标记，`plant()` 检查并拒绝，
回合开始（`stepRoll`）时清空。

## 延时气象卡

| | 旧规则 | 新规则 |
|---|---|---|
| 气象站 | 立刻对所有作物统一奖惩 | **只发一张卡，不结算** |
| 何时生效 | 立即 | **你下一次种植时自动发动**（一次性，用掉即消失） |
| 没种植时 | — | 卡一直留着，可以攒到关键地块再用 |

落到气象站不再有即时奖惩，而是给你一个「什么时候用」的决定权。

## 改良卡：抽到即到账 + 持有即增益

改良卡分两部分收益：

- **抽到即到账**：抽到的瞬间**一次性获得它的「面值」肥力币**（面值 5 ~ 20）。
- **持有即增益**：每张按**面值折算**持续增加收获 —— 面值 20 的卡 = **+6%**，
  面值 5 的卡 = **+1.5%**，公式 =（面值 ÷ 最高面值 20）× 6%，求和后封顶 **+48%**。

| 持有示例 | 收获增益 |
|---|---|
| 1 张面值 20 | +6% |
| 1 张面值 5 | +1.5% |
| 面值合计 15（5 + 10） | +4.5% |
| 面值合计 ≥ 160 | +48%（封顶） |

**不种作物就没有增益**——增益只在 `harvest()` 里结算。
点击卡牌 = 纯弃牌（放弃它的那份增益，不再换钱）；电脑也会在超过 8 张时自动弃牌。

## 我的三类手牌

图例上方有三个入口，点开看详情：

| 入口 | 内容 |
|---|---|
| 🌰 作物卡 | 种子卡持有量、单价、高收低收、科普链接 |
| 🌦️ 气象卡 | 待发延时气象卡列表（有卡时入口呼吸高亮） |
| 🎴 改良卡 | 持有量与总增益百分比、每张卡的说明 |

### 弹层显示「全部四个部落」，不只是你自己

首行是一条**部落统计条**（每个部落一块，显示该类卡的数量 + 「你」标记），
下面是按部落分节列出每张卡。

理由：对手手里有几张延时气象卡、几张改良卡，直接决定他下回合能赚多少，
属于**公开信息**，不该藏在对手的私手里。敌方有哪些卡、什么时候用，
本身就是博弈的一部分。

入口上的徽章仍然只显示「我自己」的数量 —— 那是玩家最需要一眼看到的东西。

### 竖列在地图左侧

`.legend-col`（三卡入口 + 我的土地与作物 + 图例）绝对定位在 stage 里，
所以图板要让开它：**`layoutBoard()` 给 `#board-wrap` 加 `margin-left`**，
而不是给 stage 加 `padding-left`。

不能用 padding 让位：那会让「可用宽 − 图板宽」恒等于一个很小的值，
从而把「竖列是否需要收窄」的判断带进振荡（实测在 272px ↔ 118px 之间来回跳）。
宽度和偏移都在 JS 里算，CSS 不管。

手机端（<1000px）竖列改为横跨 stage 底部，此时 `top` 必须显式写 `auto` ——
基线规则是桌面版的 `top:10px`。

## 📖 图鉴（参考书）

顶栏「📖 图鉴」打开。**全量卡牌一览，与谁持有无关** —— 即使一个部落都没抽到某张卡，
它也在列表里，只是标成「当前无人持有」并稍微淡一点（`opacity:.82`，不是隐藏）。

五个页签：

| 页签 | 条数 | 每张卡给的信息 |

## 赛道：严格顺时针，每步只走相邻格

棋子从右下角「起点」出发，**顺时针**沿图板外圈走一圈：

```
0-9   底边，从右到左起点（右下角）→ 底边最左（种子集市）
10-15 左边，从下往上左下角 → 青藏草甸土 → 荒漠土
16-25 顶边，从左到右  监狱（左上角）→ 黄绵土 → 右上种子集市
26-31 右边，从上往下  山东棕壤 → 江南水稻土 → 南方红壤
31 → 0  闭环回起点
```

也就是钟面上的 **4 点 → 7 点 → 10 点 → 1 点** 方向。

### 两张表必须严格同序

`data.js` 的 `TRACK[index]` 与 `cellPositions.js` 的 `CELL_POS[index]`
是**一一对应的**——棋子每走一步都按 `CELL_POS` 定位，格子的名称/类型也按 `TRACK` 渲染。
**任何一边单独改动都会让棋子在4 个转角处横穿图板。**

历史上就出过一次：两张表都按「底边 / 右边 / 顶边 / 左边」四段顺序排列，
但底边最左格的**下一个格子在几何上是左边的最下格**，于是棋子从底边最左
直接跳到右边最下（实测位移 0.855，正常步长仅 0.087，差 8 倍）。

### 转角格归属

归「顺时针先踩到的那条边」，所以四段编号是连续的、不重复：

| 转角 | 位置 | 归属 |
|---|---|---|
| 起点 +100 | 右下角 | 底边（idx 0） |
| 种子集市 | 左下角 | 底边（idx 9），然后转入左边 |
| 监狱 | 左上角 | 左边顶端（idx 16），然后转入顶边 |
| 种子集市 | 右上角 | 顶边末端（idx 25），然后转入右边 |

### 自动校验

```bash
node test/track.test.js          # 几何：邻接性 / 顺时针性 / 转角数
node test/track-content.test.js  # 内容：每格土壤与站点是否落在正确的边上
```

两道检查都基于「步长 < 0.30」这个阈值（实测正常 0.086~0.143，
断裂时 0.855，差8 倍），任何错位都逃不掉。UI 测试第 26 节
也在浏览器里跑一遍同样的校验，包括跨转角行走时逐格经过。

## 高收益作物需付费揭示

土地详情里的「作物收益表」在**付费前整张表是雾化的**—— 只看得到作物名，
所有数字位都是模糊的占位块，看不到任何金币数值。

花 **5 肥力币**做一次「土壤检测」解除雾化，**检测一次本块地永久可见**
（标题旁会挂上「✓ 已检测 · 永久可见」标记）。

对应课程要解决的 BUG「土壤数据缺失」—— 真实农业里测土配方施肥本来就要花钱。

**为什么是雾化而不是「显示保守数字」**：早先的实现是未付费时显示一份
「非适配土壤」的收益表，结果玩家照样看到一整张具体数字（还全是错值），
既泄题又误导。真正该做的是**不给数据**，而不是给一份假数据。

技术实现：`.revealtable.fogged { filter: blur(4.5px) saturate(.35) opacity(.5) }`
+ 数字位用 `.fogtxt`（`color:transparent` + `text-shadow`）渲染成模糊色块，
中间叠一个「🔒 未检测 — 数据已模糊」的浮层提示。
整表 `user-select:none; pointer-events:none`，防止选中复制。

## 架构：部落字典 + 引擎框架函数

这是全项目的**核心约定**（写在 `src/tribes.js` 文件头，测试第 17 节守着它）：

| | 职责 | 位置 |
|---|---|---|
| **部落字典** | 纯数据，只记录「它现在有什么」，**不含任何规则** | `src/tribes.js` |
| **引擎框架函数** | 所有规则/判定/结算，只读写字典 | `src/engine.js` |

### 字典的「栏目」

```js
{
  /* 静态身份（不可变） */
  tid, name, color, icon, trait,

  /* 栏目（每局变化） */
  money,                        // 肥力币
  pos,                          // 赛道格索引
  seeds:    { cropId: 张数 },// 种子栏目 ← 种什么由它决定
  hand:     [ improveId ],      // 改良栏目 ← 抽到即得面值；持有按面值折算增益
  weatherCards: [ weatherId ],  // 气象栏目 ← 下一次种植时自动发动
  lands:    { idx: { soilId, crops } },  // 土地栏目
  freeLandCards, skipTurns, extraRollLeft, extraRollCd,
  harvestedThisTurn,           // 本回合已收获过的地（防刷钱）
  log
}
```

一局游戏 = 4 个这样的字典 + 一份牌局状态（`landOwners` / 三个牌堆 / 轮到谁）。

### 规则只写一遍

「没有种子就不能种」这条规则**只在 `plant()` 里实现一次**，
四个部落自动都遵守——不需要给每个部落各写一遍：

```js
// engine.js 的 plant()
const stock = dictSeedCount(player, cropId);   // 读字典的种子栏目
if (stock <= 0) return { ok: false, noSeed: true, ... };
...
takeSeed(player, cropId, 1);                    // 写回字典
```

`buyCrop()` / `harvest()` / `drawWeather()` / `drawImprove()` 全都走同一套读写器。

### 读写器（tribes.js）

```
种子栏目  seedCount / addSeed / takeSeed / plantableCrops / hasAnySeed
改良栏目  addImprove / dropImprove / dropImproveTo
气象栏目  addWeather / shiftWeather / weatherCount
土地栏目  addLand / getLand / countLands
回合标记  markHarvested / harvestedThisTurn / clearHarvestMarks
汇总      dictSummary
```

把「怎么存」和「怎么用」分开：将来换存储结构（改 Map、做多套卡组、存档压缩）
只需要改这一小段，引擎其余部分不动。

### 附带好处

字典是**纯数据，可以直接 JSON 序列化**（测试里有断言）——
存档、回放、AI 训练数据都不需要额外处理函数引用。

## 没有种子就不能种

选种弹窗里，手里没有的作物会：灰度化、打红色「无种子」印章、
`cursor:not-allowed`、标注「✖ 无种子 · 不可种，去集市购买」、成本位显示「—」。

引擎侧返回 `{ ok:false, noSeed:true }`，不扣钱、不长苗。

**种子钱在买卡时已付**，所以种植环节 `cost` 恒为 0。种子**一片一张**：
种几片就消耗几张种子卡（种 2 片 → 扣 2 张），收益也**按片**记账 ——
每片单独计利润，收获时逐片结算，不会因为「一块地种一次」而重复计整块收益。
部落特长的「种子折扣」作用在**买卡价格**上（`buyCrop` 里）。

AI 也遵守这条：只从「手里有种子」的作物里挑；**一个种子都没有时会专门去集市买一张**，
否则它会站在自有土地前什么都干不了（有地有肥力但种不下去）。

**规则改动后的平衡**：种子变成硬门槛后，开局 2 张基础卡 + 集市补给成为必经流程，
平均局长 21~23 回合（与改动前持平），500 局 spread 8.4%。

## 电脑节奏：3 秒 / 快速

顶栏「🐢 3 秒 / ⚡ 快速」切换电脑每步间隔（3000ms / 600ms）。

3 秒一格、一个电脑回合约 4~8 步，三个电脑一轮要等 36~72 秒。选择存 localStorage。

### 等待提示：只显示小窗，不遮挡棋盘

电脑行动时图板正中会出现一个小窗（**转圈 + 「B 部落 行动中」+ 当前动作**）：

```
🔄 B 部落 行动中
   种植中…
   ● ● ●
```

**这个窗之外的一切都完全可见，不加任何蒙版**：

| | 做法 |
|---|---|
| `#waiting` 层 | `background: transparent`，**没有 `backdrop-filter`** —— 棋盘一格不糊 |
| `.wait-box` | 144×73（约占舞台 **1.2%**），只在正中 |
| 层的作用 | 仅拦截这期间的误点击（透明 ≠ 点击穿透） |

这样玩家能**亲眼看见电脑的棋子逐格移动、卡片翻开、日志逐条刷出来**——
这才是「电脑在干什么」的直接证据，比任何文字说明都有用。
（曾用 `rgba(250,246,236,.82)` + `blur(3px)` 的整屏蒙版，被否掉了。）

电脑之间切换时小窗不闪（AI 之间复用同一个窗），回到真人时收起，
同时掷骰键闪 1.8 秒金光。

## 棋子逐格行走

 `stepMove()` 在动画之前就已经把 `player.pos` 推到终点，中途任何 `render()` 都会让棋子
**瞬移到终点**，紧接着 `walkPawn` 又把它拉回第一格重来——视觉上就是「来回跳变」。
修法：`syncBoard2D()` 遇到带 `.walking` 的棋子就跳过定位。

另外把每格推进从 115ms 放慢到 **250ms**，CSS 过渡 0.12s → 0.22s，
每落一格给该格一个短暂高亮，一格一格看得清（方向本来就是顺时针：右下 → 左下 → 左上 → 右上）。
